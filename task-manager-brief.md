# Бриф проекта: Менеджер задач с ИИ-распределением (финал, v6)

## Статус
Проект работает, задеплоен локально, первая задача успешно создана и обработана ИИ. Дальнейшая разработка ведётся через Claude Code прямо в папке проекта — этот файл даёт ему полный контекст.

## Фактический стек (после всех правок в процессе установки)
- Frontend + Backend: Next.js 16 (App Router, TypeScript, Tailwind v4)
- База данных + Auth: Supabase (Postgres + RLS)
- Хостинг: Vercel (ещё не задеплоено — сейчас работает локально через `npm run dev`)
- **ИИ-обработка: OpenRouter** (модель `openrouter/free` — бесплатный алиас-роутер)
  - Изначально планировался Google Gemini, но бесплатный API Gemini заблокирован по гео (Google не поддерживает Россию)
  - Пробовали DeepSeek — работает технически, но требует оплаты картой не-РФ, которой может не быть
  - **OpenRouter выбран как рабочий вариант**: доступен из России без VPN, есть бесплатные модели без привязки карты
  - Реализация — обычный `fetch` на `https://openrouter.ai/api/v1/chat/completions`, без дополнительных SDK
- Шрифты: системные (Segoe UI / Consolas), НЕ Google Fonts — из-за той же проблемы с доступностью внешних сервисов Google с некоторых сетей

## Команда и права
- Ролей "менеджер/сотрудник" нет — все равноправны
- Единственное исключение: `is_owner` (boolean) — только владелец добавляет новых участников через `/team`
- Любая задача имеет автора и исполнителя (могут быть разными людьми или совпадать)
- Редактировать (текст/срок/приоритет/исполнитель) может автор ИЛИ исполнитель
- Менять статус может только исполнитель
- Удалять может автор ИЛИ исполнитель
- Комментировать может любой участник, автор комментария виден всем

## Логика ИИ
1. Автор вводит текст задачи, кому, срок и важность — всё в свободной форме
2. ИИ (через OpenRouter) получает контекст: список участников, специализации, текущую загрузку
3. ИИ возвращает: отредактированный текст (если нужно поправить формулировку), исполнителя, срок в виде даты, приоритет — сопоставляя свободные формулировки важности с одним из 3 уровней (срочно/обычный/низкий)
4. Автор подтверждает или правит вручную — ИИ ничего не сохраняет сам

## Структура интерфейса
- `/board` — общая доска: иконки участников, все задачи, поиск/фильтры, «Требующие внимания», «Выполненные»
- `/me` — личный кабинет: личная сводка, лента активности, «Мои задачи» (вкладки «Я исполнитель»/«Я автор»), требующие внимания (мои), выполненные, быстрое создание, профиль
- `/employee/[id]` — страница участника, его активные задачи, кнопка поставить ему задачу
- `/calendar` — календарь команды с полными деталями всех задач
- `/analytics` — таблица по каждому участнику: активные/всего/просрочки/среднее время закрытия
- `/tasks/[id]` — детальная страница задачи: редактирование, смена статуса, удаление, комментарии
- `/team` — только для владельца, добавление участников

## Структура БД (см. supabase-schema-final.sql)
- `employees` (id, name, email, specialization, is_owner, created_at)
- `tasks` (id, text, original_text, author_id, assignee_id, deadline, priority, status, ai_explanation, created_at, updated_at)
- `task_comments` (id, task_id, author_id, text, created_at)
- `task_history` (id, task_id, changed_by, change_description, changed_at)
- RLS: доска полностью открыта на чтение всем авторизованным; правки/удаление — по author_id/assignee_id; статус — только по assignee_id (проверяется в API, не в RLS)

## Что дальше — уже обсуждённые, но не реализованные идеи

### 1. База знаний проекта для ИИ
Цель: чтобы ИИ понимал контекст компании (термины, названия клиентов/проектов, принятые сокращения), а не только список сотрудников.
- **Простой вариант (начать с этого):** страница «Глоссарий проекта» — любой участник добавляет заметки, весь текст глоссария целиком подставляется в промпт к ИИ при каждом запросе
- **Продвинутый вариант (позже, когда накопится история задач):** семантический поиск похожих прошлых задач через embeddings + pgvector в Supabase — ИИ учится на реальной истории формулировок и распределения

### 2. Telegram-бот с дайджестом задач
- Бот через @BotFather (бесплатно)
- Участник привязывает Telegram к своему аккаунту через `/start` с уникальным кодом из личного кабинета
- По расписанию (например, каждое утро) собирается дайджест: задачи на сегодня + на неделю по каждому участнику, рассылается через Telegram Bot API
- Расписание — через Vercel Cron Jobs (бесплатно, без отдельного сервера)

### 3. Ускорение
- Сейчас медленно, потому что `npm run dev` — это режим разработки (пересборка на лету)
- После деплоя на Vercel в продакшн-режиме скорость должна вырасти в разы сама по себе
- Дополнительно можно: заменить полный рефетч доски после каждого действия на точечные обновления (оптимистичный UI); подключить Supabase Realtime вместо ручного обновления по клику

## Известные грабли (чтобы не наступать повторно)
- Google Fonts и Google Gemini API недоступны из РФ-сетей без VPN — учитывать при выборе любых будущих внешних сервисов
- HTTP-заголовки (`X-Title` и подобные) не могут содержать кириллицу — вызывает `ByteString` ошибку в fetch
- При распаковке zip на Windows стандартным архиватором папки в круглых скобках (`(app)`) иногда норовят потеряться — надёжнее использовать «Извлечь всё», а не перетаскивание файлов
- Устаревшие модели Gemini (например, `gemini-2.0-flash`) периодически отключаются Google — если когда-то вернётесь к Gemini, использовать актуальные алиасы, а не фиксированные версии
