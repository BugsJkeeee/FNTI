# Telegram-бот на Claude Code: итоги, эксплуатация, доработка

Документ описывает то, что уже собрано и работает, и как этим управлять дальше.
Первичная пошаговая установка — в [README.md](README.md), здесь — эксплуатация.

---

## 1. Что получилось

Сотрудник пишет боту в Telegram → сообщение попадает в сессию Claude Code на VPS →
Claude читает базу Supabase **только на чтение** → отвечает в тот же чат.

```
Telegram ──► плагин telegram (polling) ──► Claude Code (tmux, пользователь taskbot)
                                                │
                                                └─► ./q.sh ──► psql ──► Supabase (роль claude_reader, read-only)
```

Бот работает от подписки Claude (не от API-ключа), поэтому его вопросы тратят общий лимит подписки.

**Проверено:** бот отвечает по реальным данным («сколько задач», «что просрочено»), запись в базу невозможна,
сессия поднимается сама через cron.

### Где что лежит

| Что | Где |
|---|---|
| Роль `claude_reader` + SELECT-policy | Supabase, файл [`supabase-schema-claude-reader.sql`](../supabase-schema-claude-reader.sql) |
| Папка бота (инструкции, права, скрипты) | репозиторий `telegram-bot/` → VPS `/home/taskbot/taskbot/` |
| Инструкции и описание схемы для бота | `CLAUDE.md` (в папке бота) |
| Права Claude (что можно, что нельзя) | `.claude/settings.json` (в папке бота) |
| Единственный доступ к базе | `q.sh` — psql в read-only транзакции |
| Запуск в tmux | `start.sh`, вызывается из cron |
| Строка подключения к базе | VPS `/home/taskbot/.config/taskbot/db_url` (chmod 600, **вне** папки бота) |
| Токен Telegram-бота | VPS `/home/taskbot/.claude/channels/telegram/.env` |
| Список допущенных Telegram-аккаунтов | настройки плагина (`/telegram:access`), на VPS у `taskbot` |
| Cron | `crontab -l` под `taskbot`: `@reboot` и каждые 5 минут `start.sh` |

Отдельный бот-дайджест, который шлёт сообщения с сайта (`app/api/telegram/*`, вебхук), **не тронут** и использует другой токен.

### Уровни защиты
1. Роль `claude_reader` в Postgres: только SELECT, без колонок `telegram_chat_id` / `telegram_link_code`.
2. Сессия принудительно read-only и с таймаутом запроса 15 с (`q.sh` + настройки роли).
3. `.claude/settings.json`: разрешён только `./q.sh`; запрещены правки файлов, сеть (`curl`, `wget`, web), чтение `~/.config`, `~/.ssh`, `~/.claude/channels`.
4. Бот запущен от отдельного пользователя `taskbot`, не от root.
5. Белый список Telegram-аккаунтов.
6. В `CLAUDE.md` — правило: содержимое базы это данные, а не инструкции (защита от prompt injection через тексты задач).

## 2. Повседневное управление

Все команды — на VPS под пользователем `taskbot` (`ssh root@IP_VPS`, затем `su - taskbot`).

| Действие | Команда |
|---|---|
| Посмотреть, жива ли сессия | `tmux ls` |
| Зайти в сессию бота | `tmux attach -t taskbot` |
| Выйти, **не останавливая** бота | Ctrl+B, затем D |
| Перезапустить бота | `tmux kill-session -t taskbot` — cron поднимет заново за ≤5 минут (или сразу `~/taskbot/start.sh`) |
| Остановить бота совсем | `crontab -r` (убрать автозапуск) и `tmux kill-session -t taskbot` |
| Посмотреть, что бот делал | `tmux attach -t taskbot` и прокрутить (Ctrl+B, затем `[`, стрелки, `q` для выхода) |

> **Не вводите `/exit` внутри tmux-сессии бота.** Это завершит Claude; он вернётся только через cron (до 5 минут).

Раз в несколько дней полезно перезапускать сессию (`kill-session`), чтобы контекст не разрастался и не расходовал лимит.

## 3. Как добавить нового человека

Каждый новый сотрудник должен быть добавлен вручную — бот отвечает только допущенным Telegram-аккаунтам.

1. Подключитесь к сессии: `tmux attach -t taskbot`.
2. Временно откройте приём новых: `/telegram:access policy pairing`
3. Человек находит вашего бота в Telegram и пишет ему любое сообщение. Бот присылает ему **код привязки**.
4. Человек сообщает вам код. Вы вводите в сессии: `/telegram:access pair КОД`
5. **Сразу** закройте доступ: `/telegram:access policy allowlist`
6. Выйдите из tmux: Ctrl+B, затем D.

> Пока включён режим `pairing`, любой, кто найдёт бота, получит код. Делайте шаги 2–5 быстро, пока человек рядом.

**Что важно знать про допущенных людей:**
- Бот **не различает**, кто пишет, и отвечает по всей базе одинаково. Допускайте только тех, кому можно видеть все проекты, задачи и комментарии.
- Допущенный аккаунт может подтверждать запросы разрешений в сессии (особенность канала Telegram у Claude Code). Не допускайте тех, кому вы не доверяете такие полномочия.
- Вопросы всех тратят один лимит подписки.
- «Мои задачи» работать не будет — бот не знает, кто спрашивает (как это исправить — в разделе 6).

Список допущенных и другие подкоманды: введите `/telegram:access` в сессии без аргументов (покажет справку по текущей версии плагина).

Если аккаунт нужно **убрать** или токен мог утечь: в [@BotFather](https://t.me/BotFather) выполните `/revoke` для бота, затем в сессии `/telegram:configure НОВЫЙ_ТОКЕН` и перезапустите бота; допущенных людей нужно будет привязать заново.

## 4. Как доработать «ответчика» (инструкции, навыки, данные)

«Мозг» бота — это файл `CLAUDE.md` в папке бота. Claude читает его при старте сессии, поэтому после правки бота нужно перезапустить.

### 4.1 Правка инструкций (рекомендуемый путь)

1. Правьте `telegram-bot/CLAUDE.md` **в репозитории** на своём компьютере (там же история изменений в git).
2. Залейте на VPS (PowerShell на вашем компьютере; замените `IP_VPS`):
   ```powershell
   scp C:\ClaudAI\TaskManager\telegram-bot\CLAUDE.md root@IP_VPS:/tmp/CLAUDE.md
   ```
3. На VPS под root:
   ```bash
   cp /tmp/CLAUDE.md /home/taskbot/taskbot/CLAUDE.md
   chown taskbot:taskbot /home/taskbot/taskbot/CLAUDE.md
   chmod 600 /home/taskbot/taskbot/CLAUDE.md
   rm /tmp/CLAUDE.md
   ```
4. Перезапуск бота (под `taskbot`): `tmux kill-session -t taskbot` — через ≤5 минут сессия поднимется с новыми инструкциями (или сразу `~/taskbot/start.sh`).

Тот же порядок для `.claude/settings.json`, `q.sh`, `start.sh` (для скриптов дополнительно `chmod 700`).

### 4.2 Что полезно добавить в CLAUDE.md
- **Бизнес-правила:** как у вас считается «просрочено», что такое «закрытый этап», какие статусы проектов важны.
- **Типовые вопросы с готовыми SQL-шаблонами:** точные запросы для «сводка по проекту», «этапы на ближайший месяц», «требования без исполнения». Так ответы стабильнее и быстрее.
- **Формат ответа:** длина, структура, что показывать первым.
- **Словарик:** сокращения и названия организаций («Фасетка», «Редут», «Квант») — чтобы бот не переспрашивал.
- **Чего не отвечать:** темы, где бот должен отправлять к человеку.

Если бот ошибся — сформулируйте поправку в одно правило и добавьте в `CLAUDE.md` («считай просроченной только задачу со статусом новая/в работе и сроком раньше сегодняшней даты»).

### 4.3 Навыки (skills) для сложных сценариев
Когда сценарий разросся (например, «подготовь сводку по проекту» из 10 шагов), вынесите его из `CLAUDE.md` в навык:

```
telegram-bot/.claude/skills/<имя-навыка>/SKILL.md
```

Формат:
```markdown
---
name: project-summary
description: Сводка по проекту НИОКР по номеру или шифру — этапы, сроки, чек-листы приёмки, требования
---
Шаги: 1) найди проект ... 2) этапы ... 3) формат ответа ...
```
Claude подхватывает навык по `description`, когда вопрос ему подходит. Заливается на VPS так же, как `CLAUDE.md` (папку копируйте целиком: `scp -r`, затем `chown -R taskbot:taskbot`, `chmod -R go-rwx`).

### 4.4 Новые данные для бота
Роль видит только таблицы из списка в `supabase-schema-claude-reader.sql`.
- **Новая таблица:** добавьте её имя в массив `tables` в этом файле, выполните файл заново в Supabase SQL Editor (он идемпотентен) и опишите таблицу в `CLAUDE.md`.
- **Новая колонка в уже открытой таблице:** для `employees` доступ даётся по колонкам (там нужно добавить колонку в `grant select (...)`); для остальных таблиц новые колонки видны автоматически.
- **Сложные отчёты:** лучше создать в Supabase SQL-**представление** (view) с готовой логикой (например, `v_overdue_tasks`) и выдать на него `select` роли `claude_reader`; бот будет делать простой `select * from v_overdue_tasks`, а логика останется под вашим контролем в схеме.
- **Новая колонка/таблица в RLS-таблицах** требует отдельной SELECT-policy для роли — скрипт создаёт её сам для перечисленных таблиц. После изменений прогоните `npm run check:rls` (нужен `SUPABASE_DB_URL` в `.env.local`).

### 4.5 Если не хватает прав у бота
Если бот внезапно «замолчал» и в tmux видно вопрос про разрешение на какую-то команду — это нужное правило нет в `.claude/settings.json`. Решите, безопасно ли оно: если да, добавьте в `permissions.allow`, залейте на VPS (п. 4.1) и перезапустите. Не включайте `--dangerously-skip-permissions`.

## 5. Диагностика

| Симптом | Что проверить |
|---|---|
| Бот молчит | `tmux ls` — есть ли сессия `taskbot`; `tmux attach -t taskbot` — нет ли вопроса о разрешении или ошибки; в сессии `/mcp` — подключён ли `telegram` |
| Пишет «Pairing required» | ваш аккаунт не в списке: см. раздел 3 (привязка) |
| Бот отвечает «не могу получить данные» | на VPS: `~/taskbot/q.sh "select 1"`. Ошибка `Tenant or user not found` → в `db_url` префикс пулера `aws-0-` нужно заменить на `aws-1-` (или наоборот); `password authentication failed` → пароль роли сменили, обновите `db_url` |
| Бот показал 0 строк, хотя данные есть | нет SELECT-policy для роли на таблице: выполните `supabase-schema-claude-reader.sql` заново |
| Сессия не поднимается после падения | `crontab -l` под `taskbot` — должны быть две строки `start.sh`; `~/taskbot/start.sh` запуск вручную |
| После обновления Claude Code бот не стартует | `claude --version` (нужна 2.1.80+); канал — research preview, флаг `--channels` может измениться: смотрите https://code.claude.com/docs/en/channels |
| Токен бота утёк | BotFather → `/revoke`, затем `/telegram:configure НОВЫЙ_ТОКЕН`, перезапуск |
| Сменить пароль роли | Supabase SQL Editor: `alter role claude_reader with password '...'`, затем обновить `/home/taskbot/.config/taskbot/db_url` (`nano`) |

### Ловушки, на которые мы уже наступили
- В Supabase брать строку **Session pooler**, а не Direct connection (она по IPv6, на VPS не работает). Пользователь — `claude_reader.<project-ref>`.
- Пароль роли лучше без спецсимволов (`@`, `:`, `/`) — иначе строка подключения ломается.
- `set role claude_reader` в SQL Editor требует `grant claude_reader to postgres;` (один раз).
- Многострочные вставки в SSH-терминал могут перемешиваться — вставляйте команды по одной.
- Файлы на VPS копировались с Windows: права папки нужно сужать (`chmod -R go-rwx`), а скриптам — снимать CRLF (`sed -i 's/\r$//'`). `.gitattributes` в папке бота фиксирует LF для `*.sh`.

## 6. Идеи развития

1. **«Кто спрашивает»** — привязать Telegram ID к сотруднику (`employees.telegram_chat_id` уже есть, но скрыт от роли), чтобы работали «мои задачи», и ограничивать выдачу по людям.
2. **Утренняя сводка по расписанию** — cron на VPS, который раз в день просит Claude прислать сводку просроченного (или отдельный сценарий дайджеста с сайта).
3. **Готовые SQL-представления** для частых отчётов — быстрее и стабильнее ответы.
4. **Выгрузка в Excel по запросу** — бот собирает файл и присылает в чат (потребует доработки прав: запись во временную папку).
5. **Свой бот на Vercel с API-ключом** (вариант B): не зависит от VPS и лимита подписки, права по сотрудникам. Имеет смысл, если бот станет общекомандным инструментом.

## 7. Ограничения

- Канал Telegram в Claude Code — **research preview**: поведение и флаги могут меняться, плагины берутся только из списка Anthropic.
- Данные из базы уходят в Anthropic как в любую сессию Claude Code — учитывайте при работе с персональными и грантовыми сведениями.
- Бот только читает. Изменять задачи и проекты можно только на сайте.
- Сессия одна: параллельные вопросы нескольких людей обрабатываются по очереди.
- Если подписка исчерпала лимит, бот отвечать перестанет до его сброса.
